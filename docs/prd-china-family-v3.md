# Aurelio 中国一线城市家庭版 PRD（v3-CN）

> 状态：提案稿（PRD，尚未进入开发）
> 范围：在 v2 中国本地化（数据口径、账单导入、行情、税制）之上，把产品从**"一个人的资产台账"**升级为**"一个家庭的财务操作系统"**，并整体改造视觉与交互以符合中国用户审美与使用习惯。
> 前置阅读：[README.md](../README.md)、[docs/how-aurelio-reasons.md](how-aurelio-reasons.md)、[docs/prd-china-v2.md](prd-china-v2.md)、根目录 `ROADMAP.md`。
> 阅读对象：产品/设计/开发。所有功能项标注优先级（P0/P1/P2）与验收标准，可直接拆任务。

## 0. 背景：为什么在 v2 之后还要 v3

### 0.1 v2 已经解决的（现状盘点）

截至本 PRD 撰写时（2026-10），v2 的本地化工作已部分落地：

| v2 承诺 | 现状 |
|---|---|
| 分类词表本土化（餐饮/人情/社保公积金/个税……） | ✅ 已落地，`taxonomy.py` 后端统一词表 + 旧码兼容 |
| 支付宝/微信账单导入 | ✅ 全链路已落地（GBK 编码、幂等去重、批次撤销、转账配对、47 条商户分类种子） |
| A 股/港股/场内基金代码体系 | ✅ `prices.resolve_symbol` 支持 6 位代码归市、110 段歧义处理 |
| 国内行情源 | ✅ 腾讯行情/K 线 + 东方财富分红；场外基金净值/分红（T+1 `confirm_date` 已建模） |
| 中国税制 | ✅ 股息红利差别化（持股 ≤1 月 20% / ≤1 年 10% / >1 年免征）、A 股价差暂免，"估算永不入总额"红线保留 |
| 本位币 CNY | ✅ 默认 CNY，词表/导入/演示为人民币口径 |
| 汇率源 CFETS 中间价 | ⏳ 仅插槽（`use_rate_source`），国内源无历史数据接口，仍是 ECB |
| 银行/券商 CSV 导入 | ❌ 仅枚举预留，解析器未实现 |
| 商户分类规则 500 条 | ⏳ 现 47 条 |

### 0.2 v2 没有回答的问题：产品形态仍是"海外个人投资者"

v2 让**数据**变成了中国的，但**产品**还是欧洲的。把当前产品放进上海一个三口之家的日常生活，会看到一排硬断层：

| 一线城市家庭的真实财务生活 | 当前产品 |
|---|---|
| **一家人**：夫妻各有工资卡/证券账户/支付宝，钱是共同的，账是分开记的 | 单用户单库，全库无"成员"概念；账户、收支、目标均无归属人 |
| **每月 15 号发薪、20 号还房贷、月底还信用卡**，家庭财务以"账单日历"运转 | 无预算、无账单日历、无还款日提醒；支出是 `amount × frequency` 的抽象周期流 |
| **月度复盘**：这个月花了多少、超了没、下月注意什么（随手记/钱迹/支付宝年度账单养成的习惯） | Dashboard 只有储蓄率一根 meter，无预算 vs 实际、无月度对比、无复盘 |
| **房贷是家庭第一大负债**：组合贷（公积金+商贷）、LPR 重定价、提前还贷 vs 投资的决策 | Liability 只有"某日余额"时间序列，无还款计划/月供/利息/提前还款测算，月供也不进现金流循环 |
| **孩子教育、父母养老、换房首付**是家庭三大目标，需要按年倒推每月存多少 | Goals 的 current_amount 纯手填，无进度、无自动归集、无教育金/首付模板 |
| **保险是家庭底盘**：重疾/医疗/意外/惠民保/年金险，年缴大额、保额缺口要看见 | 完全没有保险台账 |
| **个税是家庭大事**：专项附加扣除（房贷/子女教育/赡养老人）、年终奖单独计税 vs 并入综合所得、每年 3–6 月汇算清缴 | 税模块只有投资端（股息/价差），工资薪金个税"自认另一张表" |
| **钱在支付宝/微信/银行卡/信用卡/花呗白条里流转**，信用卡有账单日、花呗有免息期 | 导入只有支付宝/微信 CSV；花呗/白条/信用卡分期无建模 |
| **用手机记账**，地铁上三秒记一笔；桌面只是月底看报表 | 桌面优先：无移动端布局、无底部导航、无快捷记账；ChatRail+面板在手机上占掉半屏 |
| **看盘直觉是红涨绿跌**，数字希望看到"1.23 万"，日期是"10 月 20 日" | 绿涨红跌（欧美惯例）、纯拉丁字体、无万位缩写 |

### 0.3 v3 目标（按优先级）

| 优先级 | 目标 | 一句话验收 |
|---|---|---|
| P0 | **家庭账本**：成员、归属、合并视角 | 夫妻各自记账，任一端能看合并净资产、成员维度收支，双计为零 |
| P0 | **预算与月度复盘** | 每月自动生成家庭复盘：预算 vs 实际、超支归因、下月建议，一键进入聊天深聊 |
| P0 | **账单日历与现金流预测** | 发薪/还贷/信用卡/保费等固定日子上日历，未来 30/90 天现金流预测与"会不会紧"提示 |
| P0 | **负债 2.0**：组合贷、还款计划、提前还贷测算 | 录入组合贷即出还款计划；提前还贷 10 万 vs 拿去投资的对比一页说清 |

| P1 | **个税与社保公积金** | 专项附加扣除采集、税前/到手拆解、年终奖计税两方案对比、汇算清缴提醒 |
| P1 | **家庭保障台账** | 录入保单（投保人/被保人/保额/保费/缴费期），算家庭保额缺口，保费进现金流 |
| P1 | **支付生态深化** | 银行卡/信用卡账单导入、花呗/白条分期建模、截图 OCR 记账 |
| P1 | **年度家庭财务报告** | 一年结束自动生成"我家这一年"：收支全景、资产增值、目标达成、一句话总结 |
| P2 | 增值项 | 理财/存单到期提醒、家庭会议模式、惠民保/税优健康险提示、CFETS 汇率源、券商/银行解析器补全 |

### 0.4 非目标（明确不做）

- ❌ **不做云端多用户/家庭共享账号**：仍是本地单机单库（v2 红线保留）。"家庭"是**一个库内的多成员归属**，不是多人登录协作。若未来要做夫妻同步，走"导出/导入加密备份 + 局域网配对"另立 PRD。
- ❌ 不做代扣代缴/报税申报（个税只做**估算、两方案对比、提醒**，沿用 `tax.py` 的"declared estimate"原则）。
- ❌ 不做券商下单/银企直连自动抓取（合规红线，v2 不变）。
- ❌ 不做社区/晒单/UGC/理财销售导流（产品定位是"家庭财务的账本与参谋"，不是流量平台）。
- ❌ 不改"锚点 + 事件"核心模型、不改卡片确认机制（`how-aurelio-reasons.md` 的规则一条不破）。

## 1. 用户画像与核心旅程

### 1.1 画像：陈昊 & 林悦家（上海浦东）

| 成员 | 基本情况 | 财务触点 |
|---|---|---|
| 陈昊（35） | 互联网大厂技术专家，税前年薪 85 万 + 年终奖 15 万 | 工资卡（招行）、证券账户（中信，A 股+场外基金）、公积金账户、公司年金、支付宝/微信 |
| 林悦（33） | 外企财务经理，税前 45 万 | 工资卡（汇丰）、信用卡（招行/浦发）、基金定投（蚂蚁）、支付宝/微信 |
| 女儿（5） | 幼儿园大班，2027 年入小学 | 教育金目标、英语/钢琴培训、医疗险 |
| 双方父母 | 男方父母合肥（退休金 6k/月）；女方父母南通（慢性病长期用药） | 赡养支出、父母医疗备用金 |

家庭财务全景：房产 89㎡（2021 年购入 520 万，现估值 580 万）+ 组合贷剩余 268 万（公积金 92 万 + 商贷 176 万，LPR−20bp，月供 1.45 万）；金融资产约 165 万（A 股 68 万、基金定投 32 万、银行理财 45 万、货基/零钱 8 万、公积金 26 万、年金 12 万）；信用卡当期 1.2 万、花呗 3 千。月度到手约 4.6 万，月供 1.45 万、教育 4 千、生活消费 1.2 万、赡养 2 千、保费摊月 2 千。

**这个画像里藏着产品的全部需求**：双人双渠道记账、房贷决策、教育金、赡养与医疗、年终奖计税、保险年缴、35 岁职业风险与应急金、换房计划。

### 1.2 财务生活的节奏

- **每天**：地铁上随手记一笔（午餐、打车、外卖）；晚上扫一眼"今天花了多少"。
- **每周**：周末看一眼持仓红绿；把没记上的大额补上（培训费、超市）。
- **每月**：15 号发薪（两人工资+公积金到账）、20 号还房贷、月底还信用卡/花呗；月初家庭复盘——"上月超了 2300，主要是孩子换牙和聚餐"。
- **每季/每年**：春节人情、暑假旅行、保险年缴（11 月）、3–6 月个税汇算清缴、年终奖到账（次年 1 月）、年度总结。
- **偶发但重大**：提前还贷 20 万、换房、孩子升学、父母住院、裁员/跳槽。

## 2. 现状功能盘点与差距诊断

### 2.1 今天能做什么（能力清单摘要）

| 页面 | 能力摘要 |
|---|---|
| Dashboard | 净资产大数字、四条 Stat 带、净资产面积图、资产配置条、月度现金流（储蓄率 meter） |
| Portfolio | 全家持仓表（成本/盈亏/分红政策）、基金穿透（国家/行业/重叠）、税务估算、投资流水录入 |
| Records → Wealth | 机构→快照→持仓三级管理、现金锚点、快照继承与重新定价、现金投影句（可跳转补录） |
| Records → Cash flow | 收入/支出/定投计划/转账录入、账单导入（支付宝/微信 CSV）、储蓄率 |
| Records → Debts / Real assets | 负债余额时间序列；房产/车等估值时间序列（资产净值 = 估值 − 关联负债） |
| Profile + Goals | 问卷画像、税率声明、基准货币；目标登记 + 所需收益率测算 |
| Chat + Analysis | AI 读全库问答、卡片确认写入、网页搜索、四步对抗式分析链（Analyst/Confidant/Revision/Synthesis） |

### 2.2 差距诊断：三层断层

**第一层 · 家庭协作层（结构性缺失）**——单用户模型是所有家庭场景的总堵点：无成员、无归属、无合并视图、无"谁花的"。这不是加字段的事，是产品主语从"我"到"我们"的变化。

**第二层 · 规划与闭环层（功能半成品）**——有周期流没预算、有负债没还款计划、有目标没进度、有储蓄率没复盘、有个税缺口。中国家庭的财务是"预算—执行—复盘—调整"的闭环，当前产品只有"记录—展示"。

**第三层 · 体验审美层（水土不服）**——西式编辑排版风（衬线标题、发丝线表格、大留白）、绿涨红跌、无移动端、无深色模式、无万位缩写。信息密度偏低，"看一眼就走"的场景每次都要滚动。

## 3. 产品原则

### 3.1 保持不变（v3 不破的底线）

1. **锚点 + 事件 = 现状**：快照重定基防双计的模型不动。
2. **卡片确认**：AI 任何写入必须经卡片人工确认（light/diff 两档），不新增绕过路径。
3. **本地优先**：数据全在 `backend/data.db`，出网请求逐项可见可关。
4. **估算如实**：税、收益、预测一律标"估算"，可覆盖，永不混入实测总额。
5. **一个数字只有一个家**：`Focus` 跳转机制（一个词的唯一录入处）保留并扩展到新对象。

### 3.2 v3 新增原则

1. **家庭即账本**：每条钱的记录回答三问——谁的、哪来的、到哪去。成员归属是第一维度，不是备注。
2. **闭环大于记录**：每个新功能都必须回答"记下来之后呢"——复盘、提醒、决策三件套至少配一件。
3. **手机优先（Mobile First）**：新功能默认按 390px 设计，桌面是增强不是起点。3 秒内完成一笔记账是硬指标。
4. **中国金融直觉**：红涨绿跌、万位缩写、账单日历、还款日心智；A 股/基金/理财的语言就是产品的语言。
5. **克制的智能**：AI 的价值在"替你算清两个方案"和"提醒你忘记的事"，不在"替你做决定"。

## 4. 功能迭代详细设计

### 4.1 P0-1 家庭账本：成员与归属

**用户故事**：作为家庭的记账主力，我要给每笔收支/账户/目标打上成员标签，让我和爱人各记各的、合看全家，还能知道"孩子这个月花了多少"。

**数据**（详见 §6）：新增 `Member` 表（昵称、角色 `self|spouse|child|parent|other`、颜色/头像）；`CashEntry/IncomeSource/Expense/Transfer/Transaction/Institution/Goal/Liability/RealAsset` 增加可空 `member_id`（空 = 共同/家庭）。

**需求**：

1. **成员管理**：Profile 页新增"家庭成员"区块，增/改/删成员（默认含"我"）；成员删除时其归属记录转为"共同"。
2. **归属录入**：所有录入表单第一行出现成员选择器（头像胶囊），默认上次选择的成员；账单导入时可按来源默认归属（如"招行信用卡 → 林悦"，规则可配）。
3. **视图切换**：Dashboard/Portfolio/Cash flow 顶部出现成员过滤条：`全家 | 陈昊 | 林悦 | 女儿 | +`。**过滤只影响展示，不改数据**；被过滤隐藏的行数在页脚明示（"另有 128 笔未显示"），防"过滤开着忘了关"的静默丢账。
4. **合并净资产**：Dashboard 拆分卡改为"家庭净资产 = 成员 A + 成员 B + 共同"，点击成员色块下钻。
5. **成员收支对比**：Cash flow 页新增成员维度条形图（谁挣的、谁花的、各分类下谁花得多）。
6. **无归属迁移**：存量数据全部落"共同"，提供批量标注工具（按机构批量指定成员：`招行工资卡 → 陈昊`）。

**验收**：
- 两个成员各录 10 笔收支，切"全家/单人"视图数字正确，合计 = 各成员 + 共同，双计为 0。
- 按机构批量归属后，历史导入流水立即正确归人。
- AI 聊天提问"我爱人这个月花了多少"能按成员过滤回答（新增 `member` 上下文到 chat tools）。

**边界**：成员只有归属与视角含义，**不做权限隔离**（本地单机，谁打开都能看全部）；不做成员独立登录。

### 4.2 P0-2 家庭预算与月度复盘

**用户故事**：作为家庭财务负责人，我要每月给分类设预算并看到执行进度，月底自动出复盘，知道超在哪、下月怎么调。

**预算（Budget）**：

1. **两级预算**：总预算（月度家庭支出上限）+ 分类预算（餐饮/教育/交通/人情……来自 taxonomy 词表）；支持"每月固定"与"仅本月"两种。
2. **预算来源建议**：首次启用时按近 3 个月实际支出自动生成建议预算（P50 分位），用户可调；教育/保险等大额年缴类按"年额 ÷ 12"摊入月预算。
3. **进度展示**：分类行显示 `已花/预算` 进度条 + 剩余天数日均额度（"这个月每天还能花 182"）；超 80% 黄、超 100% 红。
4. **预算不阻断**：超预算只提示不禁止（与现有"超支警告只提示"原则一致）。
5. **未花完的处理**：可配置"结转下月"或"不结转"（默认不结转；教育金类目标建议走"结转进目标"）。

**月度复盘（Monthly Review）**：

1. **自动生成**：每月 1 日生成上月复盘卡片，内容：收支总览（环比 ±%）、预算达成（超支分类 Top3 与归因——来自明细行聚合：商户/成员/备注）、储蓄率、净资产变化、目标进度变化、账单完成情况（"3 笔待补录"）。
2. **归因说人话**：例句模板"本月超支 2,340 元，主要是【教育培训】（+1,800，女儿换牙）和【餐饮】（+540，朋友聚餐 3 次）"——归因取自分类环比 + 备注关键词，不编造。
3. **下月建议**：基于规则给 3 条以内建议（"人情预算连续两月超支，建议调至 1,200"），每条可"接受/忽略"，接受直接改预算。
4. **进 AI 深聊**：复盘卡片一键"和顾问聊聊这个月"，把复盘数据作为上下文带入聊天。
5. **复盘存档**：按月列表可回看，形成"家庭财务月报"时间线。

**验收**：
- 设置 6 个分类预算，导入真实月度账单后进度条、日均额度、超支预警全部正确。
- 复盘生成后归因与明细对得上（抽查 3 条归因，每条能点进对应明细行）。
- 复盘数据可被聊天引用（"为什么上月超了"有据可答）。

### 4.3 P0-3 账单日历与现金流预测

**用户故事**：作为还着房贷的双职工，我要在日历上看到每月固定要来的钱和要走的钱，提前知道哪天卡里会紧。

**账单日历（Bill Calendar）**：

1. **事件源**：现有周期流（收入/支出/定投 PAC）自动上历；新增 `BillSchedule` 实体补充非消费类节点：信用卡还款日（每卡账单日/还款日）、花呗/白条还款日、房贷扣款日、保费扣缴日、房租、孩子学费（学期制）。
2. **日历视图**：月历格子内以小圆点/金额条显示当日进出；点击某日展开当日清单（来源账户、金额、是否已发生）。
3. **发薪日模型**：支持"每月 N 日"与"每月最后一个工作日"两种表达（国内发薪现实），工作日判定按 `Asia/Shanghai` 节假日表（内置近 3 年）。
4. **提醒**：本地提醒（应用内铃铛 + 可选系统通知）在还款日提前 N 天（默认 3 天）提示"招行信用卡 3 月 20 日还款 8,432 元，工资卡余额 1.2 万，够"。不做短信/推送服务（本地优先）。

**现金流预测**：

1. **未来 30/90 天预测表**：以今日各账户现金投影为起点，叠加未来账单日历事件，按日给出预计余额曲线（Dashboard 卡 + 详情页）。
2. **缺口预警**：任一账户预计余额 < 0 的日期标红，并给归因（"3 月 20 日房贷 14,500 + 信用卡 8,432，工资 3 月 15 日到账 23,000 后余额 1.1 万"）；跨账户资金调度建议（"从货基赎回 1 万可覆盖"——只建议，不自动转账）。
3. **不确定性标注**：预测线上未发生的周期流以虚线/浅色呈现，图例写明"含 5 项预计发生额"。
4. **与净资产预测联动**：目标页"照此计划 X 年后达成"的推演改用同一预测引擎（替换纯手填 monthly_contribution 的单点计算）。

**验收**：
- 录入房贷扣款日 + 信用卡还款日 + 发薪日后，日历正确渲染；跨春节的"最后一个工作日"发薪落在正确日期。
- 构造"月中大额支出 + 月末还款"场景，缺口预警在扣款日 7 天前出现，归因句完整。
- 预测曲线与实际发生后回填的历史对比，误差来源可解释（在途/未录入）。

### 4.4 P0-4 负债 2.0：房贷、分期与提前还贷

**用户故事**：作为背着组合贷的家庭，我要看清每月还款结构、剩余利息，并在"提前还贷 vs 投资"之间做出不后悔的决策。

**房贷建模（`Liability` 扩展）**：

1. **组合贷拆分**：一条房贷可拆"公积金部分 + 商贷部分"两个子额度（各自利率、剩余本金），合并显示总月供。支持 LPR 浮动（重定价日 = 每年 1 月 1 日，可改）：用户更新 LPR 后，重算剩余还款计划并留痕。
2. **还款计划生成**：录入贷款额/期限/利率/还款方式（等额本息/等额本金）/已还期数 → 自动生成逐期计划表（期数、月供、本金、利息、剩余本金）；`LiabilityBalance` 手工余额成为"对账锚点"——计划表与手工余额差异明示（"计划剩余 268.2 万，你录入 268.0 万，差 2,000 可能是提前还款"）。
3. **月供进现金流**：还款计划自动为 Cash flow 生成月度 `Expense(debt_payment)`（只读投影，不可重复录入；提前还款另记 `Transaction` 类事件或独立支出）。
4. **利息视图**：负债页新增"已付利息/待付利息"统计（按自然年分组），年度报告引用。

**分期建模（花呗/白条/信用卡分期）**：

1. `Liability.kind` 扩展 `huabei | baitiao | credit_card_installment | consumer_loan | mortgage_cn`；新增 `installment_plan`（期数/每期本息/手续费率）。
2. **实际利率提示**：手续费率按 IRR 反推实际年化（复用 `planning` 的数值方法），界面双写"名义费率 7.2%，实际年化 13.0%"。
3. 免息期内（花呗/白条/信用卡）按"流动性负债"显示在"本月待还"而不是长期负债，避免家庭杠杆虚高。

**提前还贷测算（本迭代招牌功能）**：

1. 输入提前还款金额 + 方式（缩短年限/减少月供）→ 输出：节省利息总额、月供变化、还清时间变化。
2. **对照方案**：同金额留在市场（按用户声明的期望收益率，默认 5%）的终值对比；输出一页"决策卡"：`省息 X 万（无风险）vs 预期收益 Y 万（有波动，区间 Z）`，并列提示机会成本口径（"你的房贷实际利率 3.9%，税后"）。
3. **决策留痕**：测算可保存为"决策记录"（不动任何余额），与 Analysis 链共享阅读页；实际执行后在负债页记一条提前还款事件，自动重算计划。

**验收**：
- 录入 310 万 30 年组合贷（公积金 3.1% / 商贷 4.0%）：月供、逐期结构、剩余本金与银行 app 对得上（±1 元内）。
- 提前还 20 万（缩年限）测算的省息额与手工计算一致（±0.5%），决策卡两方案数字自洽。
- 花呗 12 期分期显示实际年化 ≈ 13%（名义 7.2% 场景），且分期月供出现在现金流预测里。

## 5. 视觉与交互改版：从"西式排版风"到"中国数据卡片风"

### 5.1 现状诊断（为什么"不像中国 App"）

| 维度 | 现状（Editoriale 风格） | 中国主流审美（支付宝/微信/随手记/钱迹） | 用户感受 |
|---|---|---|---|
| 涨跌色 | 绿涨红跌 | **红涨绿跌**（A 股惯例，几十年肌肉记忆） | 直觉反向，看盘心慌 |
| 字体 | Instrument Serif 标题 + Archivo 正文（纯拉丁），中文回退宋体/雅黑 | 黑体家族（MiSans/HarmonyOS Sans/思源黑体），标题加粗黑体 | 中文标题出现宋体，纸媒感、不像金融工具 |
| 底色 | 暖骨白 #faf8f3、橄榄绿点缀 | 浅灰蓝底 #f5f6f8 + 白卡片 + 品牌蓝/绿 | 米黄纸感偏"杂志"，缺"工具"的清爽 |
| 结构 | 发丝线表格、无阴影、极小圆角、编辑式数据带 | 12–16px 圆角卡片、轻阴影、大数字、进度环 | 信息密度低、扫读慢、"不够现代" |
| 数字 | 全位数（1,234,567） | 万位缩写（123.46 万）+ 明细全位数 | 大额数字读数负担重 |
| 导航 | 桌面顶部 tab + 左侧竖排 ChatRail | 移动端底部 5 tab + 中央 FAB | 手机不可用 |
| 深色模式 | 无 | 有（夜间记账是真实场景） | 夜里刺眼 |
| 情感 | 克制、冷静、"分析师口吻" | 适度激励：进度环、月报、年度账单仪式感 | 缺"家庭感"与坚持记账的动力 |

### 5.2 设计语言：**"清风账本"（Clean-Ledger CN）**

保留现设计的克制与账本感，换掉"西式杂志"的骨架，向中国金融工具审美靠拢。

**色彩 token（`index.css` `@theme` 单点改造，组件零字面量的既有架构不变）**：

| 组 | 新 token | 色值 | 语义 |
|---|---|---|---|
| 底色 | `ground` | `#f5f6f8` | 页面底（冷调浅灰蓝） |
| | `surface` | `#ffffff` | 卡片/面板 |

| 墨色 | `ink` / `ink-soft` / `ink-faint` | `#1f2329` / `#646a73` / `#8a919f` | 三级文本（对比度维持 AA） |

| 图表 | `chart-1/2/3` | `#2b5fd9` / `#00b365` / `#f59a23` | 固定序列色 |

> 涨跌反转是**法律级优先**的改动（P0）：`up/down` 四个 token + 全部引用点一次翻转，图表/装饰不受影响（既有"语义色与装饰色分离"的架构红利）。提供设置项 `涨跌配色：红涨绿跌（默认）/ 绿涨红跌`，照顾海归/港美股用户。

**字体**：

- 引入中文 webfont **MiSans**（或 Noto Sans SC / HarmonyOS Sans，按体积与授权择一；子集化常用 3,500 字，woff2 约 1–2MB，本地自托管，不依赖 CDN）。
- 标题/大数字：`MiSans Semibold/Bold`（替换 Instrument Serif 的 display 位）；正文 `MiSans Regular`；数字启用 `tabular-nums` 于表格、展示位用比例数字（现有数字排版策略保留）。
- 拉丁字母与数字可用 `Inter`/`Archivo` 兜底混排（中文优先）。
- **字号阶梯**：页面大数字 32/28px、卡片标题 17px、正文 15px（移动端）/16px（桌面）、辅助 13px——整体比现设计上浮 1px，提高手机可读性。

**组件形态**：

1. **卡片化**：`cardClass` → `rounded-2xl border border-transparent bg-surface shadow-[0_1px_4px_rgba(31,35,41,0.06)]`；发丝线表格仅保留在"投资流水账"等确需对账感的局部。
2. **数据带 → 数据卡**：StatCard 增加浅色底 + 图标位；大数字下挂"环比/进度环"小件。
3. **进度环/条**：预算、目标、储蓄率统一用环形/条形进度组件（颜色：达标绿、预警黄、超支红）。
4. **按钮**：主按钮品牌蓝、大圆角（`rounded-xl`）、高度 40/48px（移动）；危险按钮红色文字 + 浅红底。
5. **成员头像胶囊**：全应用统一成员标识（首字圆底 + 成员色）。
6. **表格降级**：移动端表格转卡片列表（标签左、数值右，金额 tabular）。

### 5.5 深色模式与情感化

## 6. 数据模型变更（增量，不动内核）

> 原则沿 v2 附录 A：新字段全部 nullable / 有默认值，Alembic 迁移保旧行语义；"锚点 + 事件"三件套（Snapshot/CashAnchor/Transaction）不动。

| 表 | 类型 | 变更 |
|---|---|---|
| `members` | 新表 | id, name, role(`self/spouse/child/parent/other`), color, avatar_letter |
| 各实体 | 加列 | `CashEntry/IncomeSource/Expense/Transfer/Transaction/Institution/Goal/Liability/RealAsset/InsurancePolicy` → `member_id` FK nullable |
| `budgets` | 新表 | year_month, member_id?, category, amount, rollover(bool) |
| `budget_actuals` | 视图/物化 | 按月聚合 `CashEntry + Expense` 实际额（供进度条） |
| `bill_schedules` | 新表 | kind(`credit_card/mortgage/installment/insurance/tuition/rent/custom`), due_day/monthly_rule, amount?, institution_id, member_id?, remind_days |
| `liabilities` | 加列 | `loan_parts` JSON（组合贷拆分）, `repayment_method`, `term_months`, `start_date`, `lpr`, `repricing_day`, `installment_plan` JSON |
| `insurance_policies` | 新表 | 险种/投保人/被保人/保额/保费/缴费期/保障期/保单号 |
| `tax_profiles` | 扩展 settings | 专项附加扣除项 JSON（按 member）、年终奖计税偏好、税率表版本 |
| `monthly_reviews` | 新表 | year_month, payload JSON, suggestion 接受状态 |
| `decisions` | 新表 | kind(`prepay_mortgage/...`), payload JSON, created_at（决策留痕，复用 Analysis 阅读页） |
| `goals` | 加列 | `template`, `auto_accounts` JSON（归集来源）, `milestone_date` |
| `cash_entries`/`transactions` | 加列 | 工资明细 `gross_amount/social_insurance/housing_fund/tax_withheld` nullable |

**现金推演不变式**：`anchor + ΣCashEntry(非转账腿) + Σ周期流 + transfers + 投资流水`（v2 公式）；预算/复盘全部从 `CashEntry+Expense` 聚合派生，不引入第三本账。

**迁移**：`member_id` 空值语义 = "共同"；提供 `POST /api/household/batch-assign`（按机构批量归属）。
